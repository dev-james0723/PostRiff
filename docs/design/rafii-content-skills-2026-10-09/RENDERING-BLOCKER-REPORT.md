## 3. Gaps

### A24 (static)
1. **No draft-to-render step.** `creation_capabilities.native_draft` emits `fields.slides[]` (`:348-349`) and `coworker/creative.plan_assets` emits exact size and safe area (`:101`). Nothing combines the two into pixels.
2. **Wrong output contract in P1.** `render()` scales into 1000×1400 and returns one JPEG per source page (`library_preview.py:174-177`). A24 needs exact platform pixels (e.g. 1080×1350), N ordered slides, and a lossless master (PNG), with JPEG only as a derivative.
3. **Typesetting scripts.** The bundle has DejaVu only (`build_document_renderer.py:37`, `:85`). Chinese (Xiaohongshu, Weibo, Zhihu, Bilibili), Japanese (note.jp), Korean (Naver, Kakao), Arabic/RTL and Indic channels (Moj, ShareChat) would render tofu. Pillow complex-script shaping needs libraqm. Whether the pinned Pillow 12.3.0 manylinux wheel exposes `features.check('raqm')` on Vercel is **unverified** and must be checked in the cloud run, not assumed.
4. **No safe-area or overflow verification.** Nothing measures whether text fits inside `safeArea` or whether it was truncated. (`text_measure.py` exists and is a candidate helper, but it was not inspected.)
5. **No draft-scoped media state.** Media is limited to `needs_input` / `attached_unvalidated` (`creation_capabilities.py:145-155`, `:362-368`). There is no `rendered_verified` state carrying per-slide hash, bytes, dimensions and order.
6. **Provenance/rights.** Lineage exists (P4), but a rendered slide must also record its inputs: draft revision hash, slide text hash, template id/version, font files with licence, any embedded Library image asset ids with their rights record, and `generatedLabel: false` (typeset, not generated).
7. **Preview.** The signed-URL viewer exists for Library (P2) but not for a draft's slide set.

### A25 (video)
1. **No encoder in production.** There is no ffmpeg, PyAV or Chromium on the Python function (`mp4_boxes.py:3`, `hosted_storage.py:383`). HyperFrames runs only on a developer machine (`build.sh:11`).
2. **No audio source.** There is no TTS anywhere in `src/postriff_phase2` (grep for tts/speech found none). Narration would need either the user's own recording or a paid TTS provider (not authorized).
3. **Verification is incomplete even for uploads.** `parse_moov` lacks codec fourcc, audio track presence, sample rate and frame rate (`mp4_boxes.py:153-191`). It does no decode or playability test. Duration and ratio are not checked against the draft format's limits.
4. **No caption artifact.** There is no SRT/VTT generation from `spokenScript`/`onScreenText`, and no burned-in caption render.
5. **No draft binding.** An uploaded video is never matched to a video-format native draft. The state stays `attached_unvalidated`.

## 4. Recommended implementation plan

### Phase S (A24), no-cost, reuse P1–P5. Estimated scope: about 450–650 LOC Python plus tests, plus a font bundle change. Roughly 2–3 focused days including cloud validation.

Use a **Pillow-first deterministic typesetter in the existing sandboxed child**. It renders exact pixels directly with `ImageDraw` and does not need LibreOffice. LibreOffice and PDFium stay available for a LinkedIn document-carousel PDF, since Pillow can also write a multi-page PDF with `save_all=True`.

Files to touch (all backend; no `web/src` edits are required for the core):
1. **New** `src/postriff_phase2/static_render.py`
   - `render_slides(spec, slides, theme, fonts) -> [{index, png_bytes, sha256, width, height, textBoxes, overflow}]`
   - Inputs: `spec` taken verbatim from `coworker/creative.spec_for(platform, fmt)` (`creative.py:41-43`) and `slides` taken from `native_draft.fields.slides` (`creation_capabilities.py:348-349`).
   - Exact canvas `spec.size`. Text is laid out only inside the `safe` insets. It wraps with measured glyph widths and fails closed with `overflow: true` instead of shrinking below a minimum point size. Slide index is drawn only if the template asks for it.
   - Run it through the same isolated-child pattern as `library_preview._isolated_output` / `__main__` (`library_preview.py:191-248`): rlimits plus `_deny_internet`. Reuse those helpers. Do not fork the sandbox.
2. **Edit** `runtime/build_document_renderer.py`: add a pinned, checksum-locked, OFL-licensed CJK font (e.g. Noto Sans CJK SC/TC/JP/KR, subset if size requires). Arabic and Devanagari Noto fonts are a follow-up if those channels are in scope. Record each font's licence file in the bundle. Bump `BUNDLE_REVISION`. Re-run the `document-runtime` CI job (`library-release.yml:66-90`) to confirm the function still fits Vercel's size limit. This is a **cloud-only** step.
3. **New** `src/postriff_phase2/draft_media.py` (or a method on the existing creation/coworker service):
   - `render_draft(workspace, draft_id, platform, format)` performs a role check (`edit`), a capacity check (same as `library_assets.assert_capacity`), then render, then `put_immutable(..., 'media', name, png, 'image/png')` per slide. Store PNG as the master, not via `stage_upload`, which would re-encode to JPEG (`hosted_storage.py:380-388`). A JPEG derivative is optional.
   - Commit one asset per slide with `lineage_record(operation="generate", ...)` (`coworker/creative.py:119-126`), extended with `{renderer: "rafii.static-render.v1", draftRevision, slideTextSha256, templateId, fonts:[{file, sha256, licence}], embeddedAssetIds, rights}` and `billing: {costUsdMicro: 0, basis: "local compute"}`.
   - Write `native.media = {state: "rendered_verified", slides:[{index, assetId, sha256, bytes, width, height}], verifiedAt, rendererVersion}`. Any later caption edit invalidates it back to `stale`.
4. **Edit** `src/postriff_phase2/creation_capabilities.py:145-155`, `:362-368`: add the `rendered_verified` and `stale` states. `ready` for image formats is allowed only when every slide's stored object re-reads with a matching hash and dimensions.
5. **Edit** `src/postriff_phase2/coworker/service.py:370-395`, `:725-734`: when a slot's `sourceType` is `designed_graphic` or quote/text card, offer "Render slides (no cost)" instead of only `needs_asset`. Keep `real_photo` / `screenshot` as `needs_asset`, since documentary claims still need real material (`creative.py:46-55`).
6. **HTTP**: one route beside the existing coworker creative route (`coworker/http.py:186-191`), plus a signed-URL preview read that mirrors `library_assets.viewer_page` (`:340-400`).
7. **UI (later, owned by the web session)**: show real slide thumbnails from signed URLs inside the existing phone mockup (P10).

Acceptance tests that would prove A24 (run remotely via `jcb test` / the content-skills cloud script, never locally):
- `test_static_render_bytes_are_real_png`: each slide starts with the PNG signature, `PIL.Image.open(...).verify()` passes, `size == spec.size` exactly (1080×1350 for Instagram carousel), and sha256 is stable for identical input (deterministic).
- `test_slide_order_matches_draft`: N paragraphs give N assets with `index` 1..N in caption order. Reordering the draft changes the order and the hashes.
- `test_text_stays_inside_safe_area`: the bounding boxes of all ink pixels (alpha/diff against the background) lie inside the `safe` insets. Over-long text returns `overflow: true` and state `needs_revision`, never a silently clipped slide.
- `test_cjk_renders_without_tofu`: Chinese, Japanese and Korean sample slides contain no `.notdef` glyph boxes (compare the glyph coverage of the bundled font with `font.getmask`). Run this in the Lambda-image CI job, because local fonts prove nothing.
- `test_provenance_and_rights_recorded`: lineage contains draft revision, text hash, font hashes and licences, `costUsdMicro == 0` and `model is None`. An embedded Library image without a rights record blocks rendering.
- `test_preview_signed_url_serves_same_bytes`: a GET on the signed URL returns bytes whose sha256 equals the stored asset hash.
- `test_render_child_has_no_network`: reuse `test_library_preview.test_network_is_denied_in_render_child` (`tests/test_library_preview.py:125`) for the new entry point.
- `test_no_provider_call`: the transport/ledger mocks record zero `reserve` rows and zero HTTP calls during a render.
- Evidence: a real cloud run attaches the rendered PNGs and a manifest (hash, dims, order) to `docs/design/rafii-content-skills-2026-10-09/evidence/`, labelled with the run ID.

### Phase V0 (A25, achievable now at no cost, no new infra): verified user-supplied video. Estimated scope: about 200–300 LOC.
1. **Edit** `src/postriff_phase2/mp4_boxes.py`: parse `trak/mdia/hdlr` (`vide`/`soun`) and `stsd` sample-entry fourcc (`avc1`/`hvc1`/`mp4a`/`Opus`). Add `{videoCodec, audioCodec, hasAudio}` to `parse_moov` output. The code stays bounded and pure-Python.
2. **Edit** `src/postriff_phase2/video_uploads.py` commit: persist those fields on the asset.
3. **Edit** `creation_capabilities.py`: let a video-format draft bind an uploaded video asset. Allow `video_verified` only when the container brand, codec, duration, aspect ratio, size and audio rule match the format's recorded limits. If the format needs captions and none is attached, the state is `needs_input: captions`. Without decode evidence, record honestly `playability: "container_verified, not decoded"`.
4. Tests: valid H.264+AAC fixture gives `video_verified`; video-only fixture on a format that requires audio gives `needs_input`; truncated `moov` gives a rejection; a script plus cover image with no video stays `needs_input` (regression for "script ≠ video").

### Phase V1 (A25, Rafii-made video): **new infrastructure, needs James's decision.** Estimated scope: 1–2 weeks.
Pick one option:
- **(a) Bundle a pinned ffmpeg (or PyAV wheel) into the Python function**, mirroring `build_document_renderer.py`: checksum-locked, ELF closure, licence recorded. ffmpeg would encode Phase-S slide PNGs plus burned-in `onScreenText` into an H.264 slideshow/motion-card MP4 within the 300 s function limit (`vercel.json:14`). Licence choice matters: an LGPL build without GPL encoders versus x264 (GPL). It needs a licence review. Function size is a risk next to LibreOffice.
- **(b) HyperFrames on a dedicated render worker** (AWS Lambda or Cloud Run via the HyperFrames CLI). This brings new cloud accounts, secrets, cost and an ops surface.
- **(c) HeyGen-hosted HyperFrames cloud.** This is a paid provider, outside current authority.

Audio: start with **user-recorded narration** (the app already has microphone permission, `vercel.json` Permissions-Policy `microphone=(self)`) or an explicitly silent, captioned format. Synthetic TTS is a paid provider and requires separate authorization and metering.

A25 acceptance (any option): the stored MP4 must be decoded end to end in the cloud test (`ffprobe -v error -count_frames` plus a full `ffmpeg -f null` decode, both in CI) with exact duration ±1 frame, the target resolution, the codec allowlist, an audio stream present when the format requires it (or a recorded `audio: "none-by-format"`), a caption file or burned-in caption hash, and poster and frames extracted from the **encoded output**, not the inputs. A draft that has only a script and cover must stay `needs_input`.

## 6. What must never happen

- **No fake renderer.** The local harness image stand-in (`agent_runtime_v2/http.py:30-37`), canned fixtures, mocked transports, the phone-mockup export (`export-image.ts`), placeholder rectangles, or a "rendered" flag without stored, re-read, hash-matching bytes must never satisfy A24/A25 or set `rendered_verified` / `video_verified`.
- **Script ≠ video.** `spokenScript`, `onScreenText`, a storyboard, a `MotionVideoJob`, a cover image or a poster frame never make a video draft ready. `creation_capabilities.py:148-150` stays authoritative until a verified MP4 asset exists. The motion planner's rule (`motion_planner.py:39-48`: no `rendered` without output, visual and audio review) applies to any future renderer.
- **No silent paid fallback.** If the free renderer fails or is unavailable, the draft stays `needs_input` with the reason. It must never route to `image_generate` (P7) or any paid TTS/video provider without explicit authorization and a ledger reservation.
- **No generated "evidence".** Documentary claims keep requiring real photos or screenshots (`coworker/creative.py:46-55`). A typeset slide is labelled typeset, and a generated image is labelled generated.
- **No unsandboxed rendering.** Rendering always runs in the rlimited, network-denied child. It never fetches remote fonts or images at render time, and never takes a URL, path or command from draft JSON.
- **No local heavy validation.** Font bundling, the Lambda-image check, ffmpeg decode tests and renderer suites run in cloud CI/JCB, not on the Mac.
- **No overwriting.** A re-render creates new assets linked by lineage. Originals and earlier renders are never overwritten (`lineage_record`, `creative.py:119-126`).
