## Evidence record

Each result must include gate ID, candidate SHA, environment/origin, timestamp/timezone, command or reproducible manual steps, actor role, redacted test-data scope, expected/actual result and evidence file paths. Screenshots alone do not prove mutation, permissions, billing or persistence. CI green alone does not prove a real-model or real-iPhone path.

The first 30 are the original sample unchanged; the 30 added by D-A53 include Hong Kong Cantonese (Traditional Chinese) and mixed English/Chinese requests, follow-ups that only make sense as later turns of their journey's conversation, partial/empty/unknown-data requests, multi-journey asks, filters, date ranges, time zones, comparisons and charts, and read-only founder summaries for J09. Run them in the plan's `runOrder` (one conversation per entry; J09 in the founder panel). Record structure, grounding, actions and usable state, not only parser success. [Amended 2026-10-09 by James, D-A53: was 30 normal generations, three per journey plus three composite.] Run nine explicit artifact edit cases, one per journey. Test malformed/truncated/error repair separately with fault injection; injected failures are excluded from the normal first-pass denominator but must exercise repair/fallback rules. These sample counts are engineering acceptance choices, not statistical reliability guarantees.

Use existing authorized validation budget and provider pricing; do not purchase service or assume unrestricted paid calls. Reserve the sample plan's affordable cost before executing. If the approved cap cannot cover the required live sample, show exactly which live cases remain unverified; do not silently replace them with fixtures or quote a fabricated success rate. Fixture/load/fault tests must remain independently runnable without paid calls.

G17 timings are chosen release targets, not predictions or vendor promises. Measure end-to-end turn time separately from presentation admission→first component→ready. Do not hide Manager latency by labeling presenter-only time end-to-end. Cold start, cache state, deployed region and device/browser must be recorded. If thresholds fail, optimize projection size, component groups, query patterns and route; do not add artificial streaming animation or omit samples.

Run deployed concurrency tests with fixture provider at 1, 5 and 20 concurrent sessions within the test environment quota. Confirm no cross-tenant data/duplicate effects, bounded query fan-out, zero subscriptions after teardown and appropriate backpressure; this is a bounded test, not certification for an arbitrary subscriber count.

## Suggested runner entrypoints

A/G create `scripts/agent_ui_validation.sh` with explicit modes `unit`, `database`, `browser`, `live`, `release`. Resolve the repo-specific Python interpreter and current test runner first; use an explicit variable such as `RAFII_TEST_PYTHON`, never a blind global pip install. The wrapper records exit codes and rejects missing required commands/test discoveries.

The existing project commands inspected are `npm --prefix web run typecheck`, `npm --prefix web run lint` and `npm --prefix web run build`. Existing Python runtime tests use unittest, and web tests include node/browser scripts. Do not blindly substitute a pytest/Vitest command that the project does not support. Register every new test in the wrapper/CI and record nonzero test counts.

Database mode must provision/use a private test DB through the existing project workflow and exercise real caller identity/row-policy paths. Live mode is explicitly budget-capped. Browser mode labels emulation versus physical devices. Release mode verifies exact SHA and fails when any required evidence is stale, blocked or absent.

## Release decision

A fixes in-scope blockers instead of merely documenting them. A/G can accept a documented upstream-data absence as correct product behavior only where that absence genuinely reflects user state; it cannot substitute for testing the service's normal path. An unreachable critical service, missing required live check or failed tenant/billing gate is a release blocker. The requested target date never changes these definitions.
