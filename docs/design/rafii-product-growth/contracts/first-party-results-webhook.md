# First-party results webhook — contract `rafii-results-v1`

Program `RAFII-PRODUCT-GROWTH-v2`, slice G2-OUT (PRD R-OUT-02, R-OUT-03; AC17–AC19). Code: `src/postriff_phase2/results/`
(`signing.py`, `model.py`, `service.py`, `http.py`). Migration `080_customer_results.sql`. Flag `RAFII_RESULTS_ENABLED`
(default off; while off every route below answers 404).

One documented way for a form, booking page, newsletter or store **that the workspace owner controls** to report the
owner's own business results to Rafii. These are the customer's results, never Rafii's subscription revenue.

What a delivery proves, and what it does not:

- A valid signature proves the event came from someone holding this connection's secret. It does not independently
  prove the business claim; Rafii labels these results **"Reported by your connected …"**, apart from results the person
  declared (**"You reported …"**) and platform metrics (**"Platform-reported …"**, not connected in this release).
- An association with a tracking link says the result carried that link's reference. It is not causal lift or revenue
  generated by Rafii.
- A synthetic or test delivery proves the transport only. Setting up a real producer and receiving real traffic is a
  rollout step for each customer, not something a test run demonstrates.

No turnkey Calendly, CRM or newsletter adapter exists. Anything that can send one signed HTTPS request per event can use
this contract.

## 1. Setup

1. The workspace **owner** opens Analytics → Business results → Connections and creates a connection (a name and what
   sends the results: form, booking, newsletter, store or other).
2. Rafii shows the **secret once** (`rfs_` + 64 hex characters). Copy it into the producer's secret store. Rafii keeps it
   only encrypted (the existing credential vault) and never shows it again. If it is lost, rotate (§6).
3. Configure the producer to `POST` to the connection's endpoint, shown with the connection:
   `https://<your Rafii app>/api/results/webhook/<connectionId>`.
4. Send a test event (`"test": true`, or the test producer in §9). It appears in the ledger with a Test label and never
   counts in summaries.

Only the owner can create, rotate, pause, resume or remove a connection. Other members see health, not the endpoint.

## 2. Request

```
POST /api/results/webhook/<connectionId>
Content-Type: application/json
X-Rafii-Signature: t=<unix seconds>,v1=<hex>[,v1=<hex>]

{"eventId":"bk_8812","type":"booking","occurredAt":"2026-10-01T15:00:00Z","amount":{"minor":4500,"currency":"usd"},"rafii_ref":"q3Z…Kd.20260930"}
```

- **Body:** exactly one JSON object, at most **16,384 bytes** (refused with 413 before it is read).
- **Signature:** `v1 = hex(HMAC-SHA256(secret, "<t>." + <exact raw body bytes>))`, lower-case hex. Sign the bytes you
  send; any change (whitespace included) invalidates it.
- **`t`** is when this delivery is sent (unix seconds). It is distinct from when the result happened (`occurredAt`).
  Deliveries are accepted when `|now − t| ≤ 300 s` (the replay window). Keep the producer's clock in sync.
- Up to **4** `v1` values are accepted (one per secret while rotating, §6).

## 3. Event fields

| Field | Required | Rules |
|---|---|---|
| `eventId` | yes | 1–120 of `A–Z a–z 0–9 . _ : -`. Unique per connection; your own id for this event. |
| `type` | yes | `click`, `lead`, `booking`, `newsletter_signup` or `sale`. |
| `occurredAt` | yes | ISO-8601 with an offset (`2026-10-01T15:00:00Z`, `+08:00`) or unix seconds; not more than 5 minutes in the future. |
| `amount` | no | `{"minor": <whole number ≥ 0>, "currency": "<3 letters>"}`, **booking or sale only**. Minor units (cents). Never send an amount for a lead, sign-up or click. |
| `reversalOf` | no | The `eventId` of an earlier event from this connection that this event withdraws (refund, cancellation). |
| `campaignRef` | no | A short label (1–80 of `A–Z a–z 0–9 _ : -`). Stored as a label only; it never creates an association. |
| `rafii_ref` (or `ref`) | no | The reference a Rafii tracking link appended (§5). Pass it back unchanged. |
| `test` | no | `true` marks a test event: shown in the ledger with a Test label, excluded from every summary and product metric. |

**Do not send contact data.** Names, emails, phone numbers, addresses and any other field not in this table are ignored
and never stored, but they should not be sent at all. Rafii stores the normalized fields above, a digest of them, and
when the event was received.

## 4. Identity, replays and corrections

- Identity is `(workspace, connection, eventId)`.
- **Exact replay** (same eventId, same normalized content, even if re-serialized): `200` with `"status":"duplicate"` and
  the original `receiptId`. Nothing changes. Retrying a timed-out delivery is always safe.
- **Conflicting replay** (same eventId, different content): `409 result_conflict`. The new version is **quarantined**,
  never applied; the original stays. The quarantine count appears in the connection's health.
- **Late events** are welcome: `occurredAt` and the time Rafii received the event are both kept; health shows the lag.
  Summaries of past periods are restated when late events arrive (each summary carries `asOf`).
- **Reversals** are append-only: send a *new* event with its own `eventId`, the same `type`, and `reversalOf` set to the
  original `eventId`. The whole original is withdrawn from summaries and shown as reversed; nothing is deleted. A partial
  refund is a reversal of the original plus a new event with the remaining amount.
  - Unknown original → `409 result_reversal_unknown` (send the original first, then retry the reversal).
  - Different type or a reversal of a reversal → `409 result_reversal_invalid`.
  - Already reversed → `409 result_already_reversed`; the delivery is quarantined.
- A person cannot amend or reverse a connected tool's events in Rafii; the tool corrects them with `reversalOf`.

## 5. Tracking links and the `rafii_ref` parameter

- A workspace member creates a tracking link in Analytics for one **public `https://` destination** (default port, no
  credentials, public DNS only; internal addresses and Rafii's own redirect are refused). Rafii creates an opaque slug.
- The public link `https://<your Rafii app>/api/l/<slug>` answers `302` to the stored destination with
  `rafii_ref=<slug>.<YYYYMMDD>` appended to the destination's own query (the day is the UTC day of the click). The
  destination never comes from the request, so the link cannot be used as an open redirect. A turned-off or unknown
  link answers 404.
- The reference identifies a link and a day, never a person. Your producer should keep it (for example in a hidden
  form field) and send it back as `rafii_ref`.
- **Association rule `rafii.result-link-association.v1`:** an event is `associated` only when its reference names a link
  of the *same workspace* and it occurred on or after the click day and at most 30 days after it (the window is stored
  per link, so a change applies prospectively). Otherwise it is `unattributed` (no or malformed reference),
  `expired_window` (outside the window) or `not_this_workspace` (another workspace's link, counted as unattributed).
  Nothing is inferred from names, addresses or timing.
- **Clicks:** Rafii counts each redirect into a per-link daily total. No IP address, user agent, cookie, fingerprint or
  person identifier is stored. Requests that look automated are counted separately as *likely bots*: crawlers, link
  previewers (chat apps, social cards), scripts and headless browsers that announce themselves, `HEAD` and prefetch
  requests, and more than 300 clicks on one link within a minute. This is a conservative heuristic; it cannot catch
  every bot. Totals are **clicks, not people**.

## 6. Secret rotation

- The owner rotates the secret in the UI. The new secret is shown once. The **previous secret keeps working for 24
  hours** (its fingerprint is shown until then), then stops.
- During the switch the producer may send two `v1` values, one per secret:
  `X-Rafii-Signature: t=1790870000,v1=<hmac with new>,v1=<hmac with old>`.
- Rotating twice within 24 hours keeps only the most recent previous secret.

## 7. Rate budget

Per connection, defaults **60 verified events per minute** and **5,000 per day** (owner-adjustable when the connection is
created: 1–600 per minute, 1–100,000 per day). Every delivery attempt, valid or not, also counts against a budget of
three times the per-minute rate, checked **before** any signature work so a flood of invalid deliveries stays cheap.
Over budget: `429 result_rate_limited` with `Retry-After` (60 s, or 3,600 s for the daily budget).

## 8. Responses

Success: `200 {"receiptId": "<uuid>", "status": "accepted" | "duplicate", "attribution": "<attribution>"}`. Nothing else
is echoed. Errors are `{"error": "<message>", "code": "<code>"}`; a quarantined delivery adds `receiptId` and
`"status": "quarantined"`.

| Status | Code | Meaning | Retry? |
|---|---|---|---|
| 400 | `result_payload_invalid` | Empty body or not one JSON object | Fix the producer |
| 400 | `result_event_id_invalid`, `result_type_invalid`, `result_time_invalid`, `result_time_future`, `result_amount_invalid`, `result_amount_not_allowed`, `result_currency_invalid`, `result_campaign_invalid`, `result_reversal_invalid` | A field breaks §3 | Fix the event |
| 401 | `result_signature_invalid` | Missing, malformed or non-matching signature | Check the secret / signed bytes |
| 401 | `result_timestamp_stale` | `t` outside ±300 s | Fix the clock, re-sign |
| 404 | `not_found` | Unknown, paused or removed connection (no detail) | No |
| 404 | `feature_disabled` | Results are not enabled on this deployment | No |
| 409 | `result_conflict` | Same eventId, different content (quarantined) | No |
| 409 | `result_reversal_unknown` | `reversalOf` names an event not received yet | After sending the original |
| 409 | `result_already_reversed` | The original was already reversed (quarantined) | No |
| 413 | `result_body_too_large` | Body over 16,384 bytes | No |
| 429 | `result_rate_limited` | Rate budget used up | After `Retry-After` |
| 503 | `results_unavailable` | Rafii can't verify deliveries for this connection right now | Later; owner may need to rotate |

The connection's health (owner view) shows the last delivery, the last event's lag, the last error code, events,
reversals and test events in the last 24 hours, the quarantine count and a data state (`available`, `partial` after a
recent error, `stale` after 7 days without events, `unavailable` when paused, removed or never used).

## 9. Test producer

`scripts/results_test_producer.py` signs one `"test": true` event and posts it. The secret is read from the environment,
never from the command line, and is never printed.

```
RAFII_RESULTS_SECRET=rfs_… python scripts/results_test_producer.py <connectionId> \
  [--base-url http://127.0.0.1:4331] [--type booking] [--amount 4500 --currency usd] \
  [--ref <slug>.<YYYYMMDD>] [--reversal-of <eventId>] [--dry-run]
```

The default base URL is the local dev harness (`scripts/postriff_dev_hosted.py`, port 4331). Plain `http` is refused
for anything but this machine.

## 10. Pausing, removal and data handling

- **Pause** stops ingestion (404) until resumed. **Remove** stops ingestion permanently and destroys the stored secret;
  results already received stay as evidence and are deleted with the workspace under the existing account-deletion rules.
- Request bodies, secrets and contact details are never written to logs, audit events or product analytics. Audit rows
  and product events carry ids, enums and counts only.
