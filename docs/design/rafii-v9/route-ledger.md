# Route / surface coverage ledger

Columns: route/pattern | main task | existing components | API/data owner | permissions | target layout | migration status | functional test | screenshots | limitations.

Status vocabulary: `migrated` (code on the shared components, behaviour unchanged) → `verified` (functional check + visual evidence in `evidence/`). Screenshots: `evidence/routes/<slug>/<width>x<height>-<theme>.png` for 8 viewports (320×740, 375×812, 390×844, 430×932, 768×1024, 1024×768, 1440×1000, 1920×1080) × dark/light in Chromium, plus 390×844 and 1440×1000 × dark/light in WebKit; per-capture console errors, horizontal overflow and axe-core (WCAG 2 A/AA) results in `evidence/routes/summary.json` and `summary-webkit.json`. The screenshots column below is generated from those summaries. Data: the local dev harness with the seeded synthetic workspace (`evidence/seed.json`): two LinkedIn accounts, two folders, drafts; research off.

"Render check" = the route loads with real harness data, the full-page capture was reviewed by eye at 1440 dark and 390 light, and the capture has no console error (unless noted). It is not an interaction test of every control on the page.
