# Page-family migration — common brief (Streams F1–F6)

You migrate existing, working Rafii pages to the approved design DNA. This is a visual and composition migration with preserved behaviour: every existing feature, route, query, action, permission gate, keyboard shortcut, deep link and data contract stays. You add no new features, remove none, and never fake a state.

Read first: `docs/design/rafii-v9/contracts.md` (foundation you must reuse), then in `docs/design/reference/rafii-v9/Rafii_Design_DNA_v8.md`: §2 (rules), §5 (materials), §6.3 (readable sizes), §7, §9 (page anatomy + action ladder), §10–§13 (controls, forms, dialogs, collections), §20 (states), §21 (your family's recipes), §22, §23, §28 (anti-patterns). Do not copy the homepage composition (no giant greeting, phone frame or carousel) onto operational pages. Each page: identity/context (PageHeader through `PageContainer` props: `pageTitle`, optional `pageEyebrow`, `pageDescription`, optional `pageAccent` for one short serif phrase; keep it functional density), WHAT/FIND/VIEW controls where the page is a collection (`Workbar`, `SegmentedControl`, `FilterPanel`, `ActiveFilters`), the work (quiet reading surfaces for dense lists/tables/forms via `Surface material='quiet'` or `rafii-quiet`; glass only for the selected/contextual/tool surfaces), one dominant primary action per active task surface (`Button variant='action'`), secondary actions `variant='glass'`, tertiary `variant='quiet'`.

How to work on each file:
1. Read the page and its feature components fully before changing anything. List the behaviours (data hooks, actions, dialogs, keyboard shortcuts, `data-tour` attributes for the onboarding tour, `aria` labels used by tests in `web/tests/*.cjs|mjs` — grep for text your page renders and keep those strings and roles intact).
2. Replace ad-hoc chrome: `bg-card ring-1 ring-foreground/10` cards → `Surface` (material by role: quiet for reading/dense, glass for a work surface or selected item); borders/dividers → spacing or `rafii-quiet` bands; colored status chips → monochrome status with icon + text (keep semantic amber/emerald ONLY where it encodes a real state distinction that text also carries — DNA §4.3; no decorative colour); tiny text (≤11px) for essential content → 12–14px; ensure ≥44px touch targets on primary controls and 16px text entry on phones (`text-base md:text-sm` pattern).
3. Empty/loading/error/permission/offline/stale/partial states → `StateMessage` with page-specific wording; never lose the recovery action the page had.
4. Dialogs/sheets already built on `Dialog`/`Sheet`/`Drawer` may stay on those primitives (they inherit the theme) but get the elevated glass look: add `rafii-elevated` and the Rafii radius via `className` on their content; use `RafiiDialogContent` only when you rebuild a dialog. Keep focus behaviour.
5. Motion: keep existing `motion/react` animations that are meaningful; remove staggered entrance of long lists; respect `useReducedMotion`/`useMotionPreference`.
6. Mobile: content first; tables become card rows below `md` where they already don't fit; no horizontal page scroll at 320px; the fixed mobile bar is 68px + safe area (the shell already pads for it).
7. Both themes: check dark and light (`.dark` on `<html>`; the ThemeModeToggle in the header) — text contrast on glass must stay ≥4.5:1 (use `text-foreground`/`text-muted-foreground`, never hard-coded greys).
8. Do not touch files outside your family list, `components/rafii/*`, `styles/*`, `lib/*` or the shell. If a shared component lacks something you need, use a local minimal composition and report the gap.

Verification before reporting: `npm --prefix web run typecheck` and `npm --prefix web run lint` pass (if a type error is clearly in another stream's in-progress file, say so precisely instead of editing it); `node --test web/tests/*.test.cjs web/tests/*.test.mjs` still passes for anything touching your area. A dev server runs at http://localhost:3100 (dev identity; shared, keep it non-mutating: do not approve, schedule, publish, delete, disconnect, or change settings; creating a throwaway draft or conversation is acceptable). To look at your pages in the built-in browser open your own tab (`tabs_create`, address it by `tabId`), set `document.cookie='active_theme=rafii; path=/'`, reload, enter the dev workspace, and view each route at 390 and 1440 width (`resize_window`). Do not start other servers. No git commands that change state.

Report: per route — file(s) touched, shared components reused, behaviours verified intact (list), states covered, what you could not verify, and any shared-component gap.
