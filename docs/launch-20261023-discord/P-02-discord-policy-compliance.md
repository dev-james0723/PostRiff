## 1. Verdict on one screen

- The behaviour in the code is mostly aligned with the Developer Policy: no direct messages, no mass mentions, no collection of passwords, no Gateway, no storage of other members' message text, least-privilege permissions (no Administrator), per-channel and per-post consent.
- The weak spots are mostly paper and process: the public privacy policy never mentions Discord (Terms 5(a)); the deletion pages promise "revoked where supported", which is not true for Discord on the PR #216 line; there is no incident-notification path to Discord (Terms 5(c)); later features may need re-review (Terms 6).
- Ranked gaps are in section 4. The two High ones are copy fixes and should be done before the verification form is submitted and before launch.
