# Official API audit

Audit date: 2026-10-05. Official documentation/schema/SDKs take precedence over requested consumer features. The catalogue is an engineering inventory; all current app/account approval and live evidence fields are unverified. `sources.json` records primary URLs and retrieved-source hashes. No browser scraping or consumer UI automation fills an API gap.

## LinkedIn details

The [Posts API](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/shares/posts-api?view=li-lms-2026-09) documents text, ArticleContent URL sharing, single media/multi-image and polls. URL ArticleContent does not author an article or newsletter. Poll duration is one/three/seven/fourteen days. Celebration content is fetch-only for external clients.

[Images](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/shares/images-api?view=li-lms-2026-09), [Videos](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/shares/videos-api?view=li-lms-2026-09) and [Documents](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/shares/documents-api?view=li-lms-2026-09) have separate initialization/transfer/status lifecycles. Videos use server-provided byte ranges, part ETags and finalizeUpload; all media must be `AVAILABLE`. PDF validation in Rafii is stricter than the provider's wider document support: original bytes, 8 MiB/300 pages, no encryption or active content; Office formats are not implemented.

[Comments](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/shares/comments-api?view=li-lms-2026-09) read organization roles ADMINISTRATOR/DIRECT_SPONSORED_CONTENT_POSTER; writes additionally accept RECRUITING_POSTER where the documented feed contract allows it. Content CREATE/EDIT/DELETE uses the separate [organization authorizations API](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/organizations/organization-authorizations/organization-authorizations?view=li-lms-2026-09). A member connection never implies Page authorization.

[Creator post analytics](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/members/post-statistics?view=li-lms-2026-09) requires native union/date/query syntax. Certain DAILY query combinations are unavailable; Rafii rejects those combinations. Organization statistics and video counters retain native provenance. Organic document statistics were not established; advertising document analytics is not substituted. [Community Management review](https://learn.microsoft.com/en-us/linkedin/marketing/community-management-app-review?view=li-lms-2026-09) and restricted `r_member_social` remain external gates.

## Meta details

The [official Threads collection](https://www.postman.com/meta/threads/documentation/dht3nzz/threads-api) covers native replies, quote/repost, media processing, Insights and current poll/long-text/ghost/GIF/spoiler/location/reply-approval additions. Long-lived tokens normally last 60 days; refresh is permitted only for a still-valid token after the required minimum age. Expired tokens require reconnect. Requests use Threads scopes, never inherited Instagram scopes.

The [Instagram Login collection](https://www.postman.com/meta/instagram/folder/1z5vxzu/instagram-api-with-instagram-login) supports professional identity/media, content and comments without requiring a Facebook Page. Selected-path location/product tagging is excluded. Accessible primary documentation did not verify the current Insights scope/metric contract or media edit/delete authoring. These rows are `audit_unavailable`, not READY. Secondary permission claims were not treated as authoritative. Messaging is a separate product/intent.

[Facebook Pages](https://developers.facebook.com/docs/pages-api/) writes require actual selected Page tasks and tokens. Feed publishing, Reel/Story upload start-transfer-status-finish, comments and insights are separate endpoint contracts. [Official Node SDK API version](https://raw.githubusercontent.com/facebook/facebook-nodejs-business-sdk/main/src/api.js) and [Python SDK API configuration](https://raw.githubusercontent.com/facebook/facebook-python-business-sdk/main/facebook_business/apiconfig.py) confirm the selected version. Messenger requires separate intentional approval.

## X details

[Official OpenAPI](https://docs.x.com/openapi.json) exposes Article draft/publish authoring; the requested conditional unsupported label is superseded by this current official contract. Account/access eligibility is still a gate. Official create-post documentation restricts quote_tweet_id to Enterprise; self-serve pay-per-use is excluded. Article content_state uses the official blocks/entities schema, not an assumed entityMap shape. OAuth2 identity/read/refresh precedes intentional post/media write groups. Media chunking and processing, alt metadata, replies/quotes/thread-parent IDs and editing/deletion use official v2 methods.

[Pricing](https://docs.x.com/x-api/getting-started/pricing) is not treated as an account invoice. The audited listed rates included post reads $0.005, user reads $0.010, post creation $0.015, URL-bearing creation $0.200 and media metadata writes $0.005. Exact endpoint/resource billing and current account credits must be checked before approving a ceiling. Rafii stores conservative per-request reservations and stops when authorization/budget is absent or exhausted. It does not charge a user's provider account to discover whether access exists.

## YouTube details

[Data API](https://developers.google.com/youtube/v3/docs/), [Analytics](https://developers.google.com/youtube/analytics/) and [Reporting](https://developers.google.com/youtube/reporting/) supply different native resources and metrics. Resumable byte recovery and processing reconciliation are separate; future `publishAt` belongs to private videos. Public/unlisted upload release requires verified project compliance. Shorts have no separate write API; aspect/duration/date/current eligibility determine classification. Monetized metrics and memberships require separate authorization.

Playlist podcast status/hero image, metadata/localizations, caption and thumbnail lifecycles, liveBroadcast/liveStream/bind/transition and Live Chat REST are official APIs. The implementation does not claim a public Community Posts write method or automate Studio. Reporting downloads use owned job/report metadata and a fixed authenticated Google hostname, bounded CSV parsing and full response hash; large export is an explicit limit.

## TikTok details

[Video Direct Post](https://developers.tiktok.com/docs/en/content-posting-api-reference-direct-post), [Photos](https://developers.tiktok.com/docs/en/content-posting-api-reference-photo-post), [inbox upload](https://developers.tiktok.com/docs/en/content-posting-api-reference-upload-video) and [media transfer](https://developers.tiktok.com/docs/en/content-posting-api-media-transfer-guide) were checked against the current 2026 documentation. Photos allow Direct Post and MEDIA_UPLOAD, title/description/cover and top-level `is_aigc`; video `is_aigc` and cover timestamp belong to post_info.

URL media must be verified HTTPS with no redirect and remain accessible during the one-hour download window. Rafii signs approved TikTok renditions for a fixed 70-minute transfer window; ordinary library delivery keeps its 10-minute maximum. Domain allowlisting is conservative exact-host verification. Photo file/dimension limits and video dimensions are validated, then the provider's current creator duration/interaction choices are rechecked. Rafii accepts verified MP4/MOV up to its own 100 MB/3-minute policy; it does not expose the provider's entire 4 GB/10-minute envelope. Provider-side codec/frame-rate rejection is surfaced; exact frame-rate/codec preflight is not currently provided by the existing bounded MP4 metadata parser.

The transfer guide also exposes best-effort cancellation of URL pulls; that operation is implemented as a separate reviewed native action and never treated as post deletion. No general public creator analytics/comments/replies/edit/delete was verified. Research API does not grant those creator permissions.

## Pinterest details

[Official v5 YAML](https://github.com/pinterest/api-description/blob/main/v5/openapi.yaml) covers identity/Boards/Sections/Pins, video media registration/upload/status, Pin/account/video metrics, Trends/ad-account audience and separately authorized catalogs/product tagging. Rafii implements a guarded credential-free RETAIL feed/product-group subset; commerce is not requested for ordinary creators. A numeric engagement count is not a comment-management endpoint.

## Rafii limits versus provider limits

Common video uploads retain the existing verified private MP4/MOV limit of at most 100 MB/180 seconds (deployment bucket may be lower). X uses MP4/140 seconds and JPEG 5 MB. PDF/GIF storage uses bounded original-byte validation; GIF is an X-only single attachment, at most 8 MiB/300 frames/120 million decoded pixels/4096 dimensions. Function upload-body limits can impose a smaller effective GIF intake size. Multi-image limits are LinkedIn 20, Threads 20, Instagram 10, Facebook 10, X 4 and TikTok 35. These are Rafii policies, not an assertion that each provider rejects all larger officially eligible input.

Quotas, review and all eligibility are dynamic. Native fields are displayed as supplied with date/source; missing values stay missing rather than zero. Rafii-derived calculations must identify their provenance separately. Unknown mutation effects are not automatically replayed for any provider.
