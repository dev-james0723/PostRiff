## 4. 公式及成本邊界

- cohort新增付費(c,channel)=qualified×trial_rate×activation_rate×paid_rate，進入月份c+conversion_delay；渠道各算後相加，不把曝光視為合格。
- 期末客=期初客+新增+回流−流失；回流只由之前lapsed pool，不含同月流失；套餐遷移matrix保總數。每月以assert檢查庫存等式。
- MRR=Σ期末套餐客×月价×折扣；annual_share按年價/12分攤。ARR run rate=MRR×12，非全年實收。模型以月末客代表當月收入/成本，無每日proration。
- 付費貢獻=扣退款/支付費的訂閱收入−直接AI/解析/索引/儲存/media−付費支持。完整成本再計未領現金的支持工時。
- 全部經營結果=付費貢獻−trial−獲客−固定infra/工程/營運+服務收入−服務成本；創辦人未收薪的產品/銷售/支持工時只各計一次。
- 全成本CAC=(渠道現金+可歸屬創辦人銷售/內容時間+該渠道trial成本及trial支持)/該cohort新付費。這些費用已在營運結果扣過，**計CAC只是分析，不再額外扣**。0新付費=>空白/undefined，非0。
- 簡化回收=CAC/每客月變動貢獻，只在貢獻>0且收入相對穩定時；忽略cohort付費延遲所以還要看實收回收期。不能當短樣本LTV。
- 簡化平衡客=固定成本/加權月貢獻；維持客群再減流失率×替補CAC。詳細例子見GROWTH。
- `cash_operating_result`是按當月收入、只扣現金成本的分析小計，尚未調整收款時間，不是銀行現金流；實際現金變化看`receipts_after_fees − cash_out`。
- 月末現金=月初+到期實收淨額−本月實付。`founder_draw`為提款/分配，不重複扣為經營費用；若已是薪酬須填對應薪酬欄及扣除重覆機會成本。

年繳預設0。`annual_20pct`壓測有年初/周年預收與月度收入分開；採同一月流失期望值，未建合約期內不退款/按日退費及完整deferred-revenue資產負債表，**僅現金敏感度示例，不可直接用於正式年繳財務**。若開啟年繳同時套餐遷移，模型拒絕，避免忽略proration。第一期先月繳。銷售稅按代收代繳概念不作收入，實際稅/法務/跨境成本仍未知，填fixed_other/fees或加ledger後才能正式預算。

同一參數單獨+20%，按月36全成本經營結果差值排序（選取的範圍/擾動會改變排名，不是假精確的市場模型）：

| paid_rate | $878 | 同一完整工作流後展示同一價/用量，記選擇、實付、退款；不訪問未激活者灌分母 |
| hourly_rate | $-837 | 逐任務記創辦人工時，填實際機會成本/可維持收入要求 |

結論：下一步不是擴廣告。用3名符合ICP的人各帶一個真實、可授權素材完成原流程與PostRiff對照，七天內看第二次是否主動回來；同時記完整時間、協助及是否願用。通過才擴至10人四週。未有安全managed route前，先做近期行為訪談/本地可用性，不能將fixture當AI有用性證據。
