# Rafii architecture audit before implementation

Base: origin/consumer-saas 91f6572c, isolated managed worktree rafii-youtube-creator. Unrelated original checkout is preserved.

OAuthService already binds expiring, single-use state/PKCE to member + workspace + provider + exact server callback, encrypts server tokens using CredentialVault, performs token refresh and disconnect/revoke, and uses immutable provider IDs. Connections key by (workspace, connection), so the same creator may connect in different workspaces. Grants from distinct channels become distinct connections; no assumption that channel title identifies an account.

HostedWorkspaceService/PostgresWorkspaceRepository enforce membership/role and optional recent-auth checks. HostedPhase2Commands, Phase2Store.build_manifest, PostgresWorker, HostedSocial and audit tables supply workspace state, exact approval manifests, idempotency keys, dispatch authorization, receipts and ambiguous-failure reconciliation. AudienceService already has inbox threads/reply drafts/approval before send. Analytics/growth use provider-source snapshots and admission gates.

Existing YouTubeProvider has Google code exchange/offline/PKCE, channel discovery, tokeninfo grant inspection and revoke. Existing HostedSocial sends a single full-file PUT, persists no durable session before sending, has only title/privacy/audience metadata, reconciles processing with videos.list, and may match an ambiguous upload by title/time. The legacy local engine assumes six uploads/day. Native scheduling is not implemented. Existing shared connector Direct levels depend on operator production_reviewed, not independent project/channel/E2E evidence.

Reuse OAuth, vault, repository authorization, storage, manifest/approval, worker, receipts, audit, API routes and UI query architecture. Add YouTube-specific independently gated capabilities and durable operation/session/usage state; private upload and processing must not become public publication. Keep broadcasts, streams, chat, playlist operations and upload resources distinct. No credential value is recorded in this audit.

Vercel marketplace discovery returned Mux; it is video hosting and does not implement the user's explicitly required Google/YouTube APIs. No integration was installed, no paid service was provisioned, no mock was substituted. Vercel CLI observed 60.1.3; a global CLI upgrade is outside this implementation.

## Implemented local candidate

The new YouTubeCreatorService is mounted in the existing HostedWorkspaceService and HostedApp. OAuthService, CredentialVault, authenticated workspace transactions, roles/recent authentication, private media storage, exact approval manifests, PostgresWorker, publishing receipts, shared comment inbox and audit records remain the shared foundation. Instagram/X/Bluesky/Telegram continue using their adapters. YouTube adds dedicated Video/Short/Live options and creator resources instead of serializing a generic text post.

OAuth uses exact server callback validation, expiring CSRF-safe state, S256 PKCE, offline access, incremental feature grants, server tokeninfo inspection, encrypted refresh tokens, channel discovery and immutable Channel ID. The one-use exchange claim is committed before Google exchange so rollback cannot replay it. Multiple workspaces and selected Google identities have separate connection rows. A refresh token is preserved only for the same non-revoked channel grant. invalid_grant purges authorized data and requires reconnect; invalid_client is a project configuration failure. A changed encryption key fails closed into reconnect; automatic dual-key re-encryption is not implemented.

Google revocation is account/project-wide. A Channel ID cannot prove that two Brand Channel grants are independent. Disconnect always purges the current workspace’s tokens and authorized content; remote revoke is conservatively deferred while another active Google connector grant exists. The UI/receipt reports that boundary. Once the last known grant is disconnected, the official revoke path is available. This protects other workspaces at the cost of possibly retaining a remote grant until its last local use is gone.

37 capability states combine official support, actual scopes, channel/action eligibility, independently recorded Google project gates, execution flag and real evidence. Actual scopes are engineering data; creator controls use human-readable feature names. Monetary/member enablement is separate and owner/recent-auth protected. Unsupported Community/Article controls are never enabled. Project and real-acceptance observations have a conservative 30-day Rafii freshness policy; this is not an expiry assigned by Google.

The official method contract contains 71 reviewed methods. The creator service exposes reviewed action previews, immutable-target confirmation, write-intent commit, exact approval digests, durable receipts, explicit unknown outcomes and read-only reconciliation. JSONB key reordering cannot change the approved part ordering/digest. Delete does not become an automatically retryable worker action.

Resumable videos.insert sessions are encrypted and committed before bytes are sent. One-MiB chunks use official offset probes; token refresh preserves the session. Ambiguous initialization, lost journal and expired sessions are held without a new upload. The lifecycle distinguishes bytes, private upload, processing, processed state, native schedule and publication. Thumbnail/caption/playlist membership are independent idempotent post-upload steps. Metadata/declarations and attachments are read back before the requested visibility/schedule is applied. Exact original-approver recovery may extend dispatch up to 36 hours for the unchanged manifest and same known session/Video ID.

Native status.publishAt is applied only to an eligible private never-published video with a future time and independent public-upload gates. YouTube’s accepted native schedule remains source of truth. Reconciliation uses official processing/upload/rejection fields and conservative background reads. Signed official WebSub hints for uploads/title/description wake readback and cannot prove processing or publication.

The dedicated creator screen and shared composer provide Video/Short modes, valid assets, title/description/tags/language/localizations, audience and synthetic-media declarations, privacy, native timing, thumbnail/captions and playlist/podcast assignment. Creator surfaces include owned video edits/deletion, native playlist/podcast resources, hierarchical Inbox/comments, Analytics templates with provenance, bounded Reporting ingestion, distinct Live broadcasts/streams and reviewed Live Chat moderation. Ordinary stream responses redact the key; its explicit fresh-owner read is transient and clearable.

Migration 089 is a candidate only. Eight YouTube tables use workspace/connection foreign keys and service-only RLS; Inbox hierarchy and committed OAuth exchange state reuse shared tables. Authorized caches/reports/chat/receipts expire within bounded retention and purge on revocation. Quota attempts/cost estimates are recorded by workspace/method/bucket; actual whole-project remaining quota stays unknown. Operational quota/upload/account/project failures appear in the creator surface and audit, with deduplication and retry holds.

Official Live Chat streamList uses Google’s TLS gRPC protocol with durable cursor/ordering and bounded eight-second batches; REST fallback respects pollingIntervalMillis. The UI currently requests batches. Continuous production streaming and a large distributed Reporting runner are not proven.
