# PostRiff interview guide

Status: research instrument, not interview findings. One question per turn; wait for the answer. Use the same core sequence for P01–P05, with short probes only for missing behavior, order, time, evidence, privacy or purchasing intent. Allow the participant's preferred language and preserve their wording.

## Before the session

For P02–P05, explain the purpose and request agreement to local written notes before substantive questions. Recording, sharing, sensitive files and provider uploads require separate permission. The participant may skip any question. Use the participant ID, not contact details. Do not present PostRiff or prices before the task story. James starts with the exact first question below; do not insert an extra consent question before it.

## A. Understand a real task

1. **RQ01–02, exact first question:** Think about the most recent social post you created—or seriously tried to create. What triggered it, and can you walk me through everything you did from the first idea or source to the final result?
2. **RQ02:** What happened next at the point where the sequence is unclear? Use this only if needed; ask about one step at a time.
3. **RQ03:** Which part required the most work or made you stop? Probe what the participant actually did next, rather than suggesting a problem.
4. **Recurrence:** When did you last do a similar task before this one? Establish cadence and whether the same difficulty recurred.
5. **RQ04:** Where was this content meant to appear? Then, if needed, ask which language/audience changes were actually made.
6. **RQ05:** Which decisions did you make yourself on this task? Follow up separately on what was delegated and why.
7. **RQ06:** What is one draft change you made because it did not sound like you? Ask for before/after wording only if they are comfortable; distinguish factual corrections from style edits.
8. **RQ07:** Which materials used in this task would you be comfortable letting a writing tool process? Follow up one at a time on local-only material, model-provider processing, business collaborators, deletion and export.
9. **RQ10:** Which AI or agent tools, if any, did you actually use on this task? Learn agent name, route if known, setup steps, help needed and abandoned setup. Do not infer authenticated capability from installation.
10. **RQ11, current behavior:** What made you come back to this workflow the next time you needed content?

Collect missing baseline fields during the story or with one short question per field. Do not ask the participant to fill a dense metric table in conversation. For final state, ask what actually happened: saved, abandoned, manually posted, scheduled or published; participant reports remain unverified unless evidence is reviewed.

Before concept testing, summarize the observed sequence and uncertainties back for correction. Do not replace the participant's account with the product's intended journey.

## B. Concept test, shown only after the task story

Say: “This is a proposed workflow. It has not been built or shown to save time. Please tell me what fits your task and what does not.” Use ordinary text cards below. A narrated interaction is a concept test, not functional usability validation. No live generation, account connection, upload, schedule or purchase is performed.

Show one step, then ask its question and wait:

| Order | Concept shown | One prompt |
|---|---|---|
| 1 | Three starting cards: Personal Brand (your experience and point of view); Role Specific (a subject or expertise); Business (an existing company). Visible Hybrid: “A mix of these.” All can change later. | Which would you choose for the task you described? |
| 2 | Supply one idea or a source you choose. Imports and account connection are optional. | What would you bring in first? |
| 3 | Review an editable voice and knowledge profile based only on supplied examples and confirmed facts; exportable as Markdown. | What would you change before approving it? |
| 4 | Choose an existing supported agent (planned Codex CLI, Claude Code, supported Gemini/Google routes) or managed AI. Local agents can still send selected context to their model provider. Routes need qualification. | Which route would you choose? |
| 5 | Receive two independent drafts adapted to the selected platforms, languages and audiences, with source notes and unknown facts visible. | What would you check first before using either draft? |
| 6 | Edit a draft; choose Remember, This post only, or Reject for a proposed preference. The next draft uses the approved revision; undo is available. | For one change you mentioned earlier, would you want it remembered? |
| 7 | Save/export, or connect the intended account, verify the needed permissions, review the exact post and schedule it. A connection is not proof of publication. | Where would you want this task to end? |
| 8 | Return with the saved brief, drafts and approved preferences intact. | What real occasion would bring you back? |

For step 1, record the unaided choice, confusion and rejected labels before explaining Hybrid further. For steps 3 and 6, use only the participant's volunteered material; if no example is available, record limited concept exposure rather than inventing a personalized profile or completed draft.

## C. Reusable workflows and memory

Explain after the eight steps: “PostRiff provides the same complete set of reusable content workflows in every plan and trial. Each person's private version uses their own voice, knowledge and preferences. James's original skills and private data are not shared with customers.”

Ask individually:

- **RQ09:** How would you want to find or choose these workflows while creating a post? Obtain an unaided response, then probe whether quiet recommendations, a visible library or both fit their work.
- **RQ09:** Which behavior would you want to configure yourself?
- **RQ05–07:** In your own words, what would PostRiff remember about you? Record teach-back before correcting misconceptions.
- **Privacy comprehension:** Who would you expect to be able to see that information? Then clarify private originals, neutral templates and private instances separately if needed.
- **RQ08:** If your personal work became a business, what should carry over? What must stay separate is a follow-up turn, not a second simultaneous question.

A comprehension answer does not certify the architecture. Record misunderstandings, local/cloud expectations and unresolved risks.

## D. Pricing and trial test

First ask: “What do you currently spend per month on tools for this workflow, if you are comfortable sharing?” Preserve currency and uncertainty. Then present the two proposed offers with equal emphasis. P01/P03/P05 see Studio first; P02/P04 see Assist first. This is an order-bias precaution, not an A/B experiment.

- Studio: $19/month, your supported agent; full generalized workflows, all modes, private personalization and export. Proposed baseline: 1 brand hub, 3 connections, 1 user, 5 GB and 300 scheduled destinations/month once those capabilities are qualified. The user's agent/provider has its own charges and limits.
- Studio Assist: $39/month, same baseline plus 100 managed standard writing requests/month.
- Every available plan has a proposed 14-day trial, no credit card, no automatic paid conversion, and a shared 10-request managed writing allowance. Switching trial plans would retain expiry and remaining requests. Business and its trial are planned later, not an available offer.
- Proposed request definition: one generation or revision, up to 3 text variants, 6,000 source words and 2,000 output words. Extended research and media generation are separate; no automatic overage.

Ask one at a time:

1. **RQ12:** After seeing this workflow, which would you choose: a free trial, $19 Studio with your own agent, $39 Studio Assist, neither, or a different arrangement?
2. What makes that choice fit your situation?
3. What would stop you from starting or continuing when the trial ends?
4. What, if anything, would you change about the trial duration or the 10-request allowance? Split these terms into separate follow-ups if the participant addresses only one.
5. What would you use instead if PostRiff did not exist?

Record concrete objections, existing alternatives and dependencies. A plan selection is stated intent. Do not enter signup, purchase, card or revenue evidence without a separate real later event. If no objection is expressed after probing, record that; do not invent one or silently mark the objection gate satisfied.

## E. Quantitative baseline fields

| Field | How to record |
|---|---|
| Recent task/date and repeat occasion | Participant words; exact date or approximate window |
| Total elapsed and active working time | Separate; measured / estimated / unknown; preserve ranges |
| Source finding/checking | Time and source verification method |
| Drafting and adaptation | Per channel/language, format and intended audience |
| Generic/incorrect AI correction | Time, before/after if supplied; whether included in drafting total |
| Tools and handoffs | Name each reported tool; count only after sequence is known |
| Variants used | Actual count and use, separate from intended count |
| Final state | Saved / abandoned / manually posted / scheduled / published / unknown; evidence level |
| Factual confidence | Participant self-rating 1–5; 1 not confident, 5 very confident; not accuracy certification |
| Voice fit | Participant self-rating 1–5; 1 not like me, 5 strongly like me |
| Monthly spend | Optional; currency, estimate period, included tools |

Do not sum overlapping times. Unknown is not zero. Keep reported confidence separate from observed correctness.
