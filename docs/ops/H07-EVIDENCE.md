## 2. The BLOCKED rule

`src/rafii_control/oncall/readiness.py`, tested in `tests/test_oncall_engine.py` (`Readiness`):

## 3. Executable alternatives while BLOCKED

1. **Name the people.** A Primary and a Backup for nights, weekends and holidays (for example a Backup in another time zone), each with a push subscription, an e-mail and a verified phone; declare night cover; then run the real tests of section 1 once (section 6, row H07-A).
2. **Option B**, a paging service with schedules, calls and its own heartbeat monitor (paid; the owner chooses the vendor), driven by the evaluator through a vendor-neutral adapter.
3. **A stop that does not live in the database, prepared in advance**: the Discord-paused staged build (`PHONE-RUNBOOK.md` lever 2; Packet 3 row 12b). A woken person can promote it instead of the database hold, and it survives a restore. It is **not** a stop that strands nothing: with no coordinator, a created post awaiting its read-back is marked uncertain at the first claim, burns a check per claim, is parked for 24 hours at the fifth (about 5 minutes at one claim a minute) and stays parked when the normal build returns (review N-1, measured with probe E5, `REVIEW-8E76AFDD-EVIDENCE.md` section 2). The code fix is with the limiter lane and is open. The automatic database hold (option D1) is **not recommended**: the hold itself strands posts on a build without the limiter's read wait (section 5, H1).
4. **Smaller exposure**: open with a smaller server cap, or keep the canary gate, until cover exists; or delay the opening. Business decisions for the owner.
