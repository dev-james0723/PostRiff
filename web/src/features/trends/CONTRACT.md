# Trust Trend Radar / Opportunity Lab contract

Canonical source: `web/src/lib/coworker/trend-types.ts` exports runtime Zod schemas and inferred TypeScript types. Generated cross-language artifact: `docs/design/social-trend-intelligence/api.schema.json`. Backend validates actual projections with the generated definitions, not a parallel handwritten approximation. JSON uses snake_case; schema_version is `1.0`.

Base: `/api/workspaces/{wid}/coworker/trends`. Session token + existing X-PostRiff-Request guard. Every response uses the common envelope; data is a list for list/language-patterns/opportunities/watches, a detail object otherwise. GET reads stored, current-permission projections only. Unknown/null values have reasons; no route starts paid acquisition or models on mount. Error body is `{code,error}`; HTTP 401/403/404/409/410/429/503 retain the master spec meaning.

Required nested structures are exported in the canonical source:

- coverageSchema: independent availability/representation/completeness/breadth; scope, scope_ref, coverage_epoch, latest_successful_read, freshness_deadline, sources[{platform,availability,reason}].
- metricSchema: value|null, unit, definition_id, definition_version, window{start,end}, baseline_ref|null, denominator|null, null_reason|null. Null values require null_reason. Windows are half-open.
- trendSchema: observed{summary,first_detected,latest_observed,metrics,timeline[{at,value,unit,state,reason}]}; calculated metric map; inferred{stage|null,data_state,explanation,confidence,calibration_state,evidence_refs}; interpretation|null {summary,language,phrases,alternatives,evidence_refs}; unverified_claims; full coverage; limitations; receipt ID; exact verification reason; expires_at; platform_states[{platform,inferred,coverage}]; rights-filtered evidence; workspace_fit|null.
- evidenceSchema is a discriminated union. Only displayable entries may have excerpt/url. Aggregate/restricted/deleted entries carry id/display_state/reason only. No restricted snippets in responses or hidden DOM.
- verification states: pending, verified, mismatch, inputs_expired, inputs_deleted, policy_revoked, method_unavailable. UI derives human labels without changing the wire value.
- canonical stages: emerging/rising/breaking/hot/peaking/saturated/declining/evergreen. Public stage needs global stage flag, receipt flag, verified unexpired receipt and qualified platform state and qualified calibration.
- workspace_fit retains seven dimensions: trend_relevance, brand, audience, timing, originality, risk, confidence. Each has assessment/reason/evidence_refs. `sufficient` gates angles. No combined score.
- receiptSchema extends trend with receipt_id and method{id,version,formula,calibration_cohort,snapshot_refs}. API rechecks current rights; historical method identity does not override revocation.
- methodologySchema, calibrationSchema, genomeSchema, propagationSchema, saturationSchema, languagePatternSchema define stored advanced projections. Insufficient calibration never displays an accuracy percentage. Graph edges label observed/hypothesized and carry refs; list is the equivalent primary accessible representation.
- opportunitySchema: current revision >=1; state candidate/ready/accepted/dismissed/expired/blocked; platform_targets; context_digest and context_revision (same frozen digest); trend_id, trust_receipt_id, verification_state, expiry; contribution/uncertainty; seven-dimension fit; up to three angles with factual requirements; source_id/draft_id nullable.
- acceptance POST `/opportunities/{id}/accept`: strict {revision,angle_id,channel_id,goal,idempotency_key,exposure_id?}; envelope data {source_id,href,verified,existing}. Saves a source for existing Ideas review. No generation or publication. Only navigate when verified and href is the expected source-local Ideas path.
- Lab POST `/opportunity-lab/runs`: strict {draft_id,draft_revision,opportunity_id,opportunity_revision,target_platform,idempotency_key}. Text/context resolved by server. labRunSchema binds exact revisions + context_revision + receipt + expiry and dimension diagnostics. GET `/opportunity-lab/runs/{id}` reads status. No on-keystroke requests. Apply edits only through existing variant_edit and current variant revision; local unsaved text invalidates a result immediately. Missing opportunity/draft linkage disables Lab. No additive client lineage fields: the server carries trendLineage from accepted source through the Ideas artifact into the variant and freezes it in the approval manifest. Existing variant_edit rechecks the current receipt/opportunity in the same authenticated mutation cursor and rolls back invalid edits.
- watches: GET, explicit POST {trend_id,platforms,threshold,notification_policy:in_app,idempotency_key}; idempotent DELETE carries expected_revision and idempotency_key query parameters. Persisted response must confirm active/disabled. No external notification opt-in here.

## Visible opportunity exposure and dismissal (additive WP16)

GET `/opportunities` alone extends the common envelope with optional `exposure_token: string|null` (max4096). The signed token binds the exact returned eligible page subset, actor, workspace, context and scope for at most five minutes. Candidate/ready entries with verified current receipts form that subset, in page order, at most20; this is not the full candidate universe.

POST `/exposures` uses strict exposureInputSchema: event_id UUID, exposure_token, opportunity_id UUID, opportunity_revision>=1, trust_receipt_id UUID, context_digest, eligible_candidates[{opportunity_id UUID,revision>=1}] min1/max20. Response exposureSchema: exposure_id,event_id,opportunity_id,opportunity_revision,trust_receipt_id,context_digest,measurement:`client_reported_view`,eligible_candidate_count,recorded_at,expires_at,existing. No client time, draft text, reason or user identifiers. Same event UUID/body is reused on a bounded retry. The server validates all current bindings; GET delivery is never counted as exposure. Client measurement requires at least500ms continuous card intersection while the document is visible; hidden/unmounted/flags-off components cannot dispatch late events.

POST `/opportunities/{id}/dismiss` uses strict dismissOpportunityInputSchema: revision>=1,idempotency_key1..200, optional exposure_id UUID. Response dismissedOpportunitySchema: opportunity_id,revision,state:`dismissed`,exposure_id UUID|null,existing. The explicit Not relevant action records no inferred reason. Accepted or changed candidates conflict409; replay rechecks rights and expiry. Acceptance may also carry optional exposure_id; omit it if exposure is missing/failed, never synthesize it. All three mutations require edit permission, INTELLIGENCE+RADAR+TRUST_RECEIPTS flags and workspace allowlist. Private workspace records carry no publication or generic telemetry authority.

## Growth Beta status and comparable feedback

Authenticated coworker `/status` adds `trend_beta` (canonical `trendBetaStatusSchema`). Radar requires the intelligence, Radar and trust flags plus explicit workspace admission. Missing or malformed status fails closed. Acquisition is `none` when the operation is off, `unverified` while admitted without a recent successful batch, `active` only after a recent durable workspace-local collection receipt, and `degraded` for a revoked, expired, paused or unhealthy source. GET reads source health and receipts only; it never queues acquisition. A recent sample does not claim platform-wide coverage.

Existing Performance adds `post_tracking` (`postTrackingSchema`), bounded to 120 verified jobs and their t0/1h/24h/7d schedules. It checks exact workspace/job/provider/account/native-post identity and current Direct analytics capability. Disabled, unscheduled, pending horizon, scheduled, pending, unavailable, unsupported provider, disconnected account and unavailable rights are separate from measured native data; zero remains a valid observed value. Reads neither schedule nor fetch metrics.

Trend learning outcomes add `comparison`: relative difference from the earlier median (null below five comparable posts or at a missing/zero baseline), sample count, evidence and counter-evidence publication IDs, reason and `causal=false`. Cohorts bind account/provider/language/format/native definition/window. Paired counters must share observation and ingestion times. Frozen publication context and lineage remain required; multi-recommendation treatment stays unknown. Only unchanged measured 24h outcomes enter existing reviewed/expiring hypotheses.

Follower conversion is unavailable: the reviewed provider-native contract registry is empty. Neither saved proxy objectives nor views/reach/account follower deltas are accepted as conversion. JEV remains an evaluator with a semantic task whitelist and cannot dispatch popularity, velocity, reach, views or follower-growth estimation. No production activation, provider admission, entitlement, scope or spend is granted by these contracts.
