# Language and localization

Writing the same idea natively in another language, without changing what it claims.

Read this with the `postriff-content-engine` SKILL.md, which stays authoritative.

## Where regional conventions live

Each destination carries a `languageId`: a BCP 47 tag such as `zh-Hant-HK`, `yue-Hant-HK`, `zh-Hant-TW` or `en-GB`. The locale guide bound for that tag (from `references/locales/`) carries the regional conventions: script and spelling, punctuation, the words that give a region away, address, formats and local rules to flag. A language with no region, or a region without a tuned guide, gets a family guide; a language with no researched guide gets the generic one.

A locale guide describes the variety, not the author. The author's voice profile decides tone and habits, and the approved facts decide content.

## Cross-language rules

- Write natively; don't translate. Keep the same underlying point, but change the opening, examples, rhythm and CTA for the audience. Keep the personal voice; don't let it read like a translated press release.
- Converting characters or swapping spellings is not localizing. Never produce one regional variety by converting another.
- Keep one regional variety per post. Don't mix markers from sibling varieties.
- Don't put a long version in each language into one caption by default. Make separate platform-native versions unless the user specifically asks for a bilingual post.
- When one channel carries two languages, write each as its own native post, not a translation of the other.
- Preserve uncertainty and qualification across languages. Never translate a claim into a stronger claim.
